# Code generation and ownership

## Goals

Generated code must read like code a C# developer would write: ordinary control flow, meaningful names, minimal parentheses, no helper runtime. It must be deterministic so unchanged graphs produce byte-identical files and clean diffs.

## Rules

- One graph → one `internal static class` in `Generated/{GraphName}.g.cs`, in the project's root namespace (file-scoped).
- `using` directives are derived from the types the IR references, sorted.
- Locals use explicit keyword types (`string line`) and `var` for other types.
- Local names come from the producing node (`line`, `line2`, …), unique per method, never keywords. Graph variables keep the name the user gave them and are declared first, at the top of the method.
- Line endings are `\n`; files end with a newline; indentation is four spaces.
- Each file starts with:

```csharp
// <auto-generated>
//     Generated by VisualStudioLikeIDE from Graphs/Program.graph.json.
//     Changes to this file are overwritten when the graph is compiled.
// </auto-generated>

#nullable enable
```

`#nullable enable` is explicit because Roslyn disables nullable analysis in `<auto-generated>` files by default.

## Ownership model

| File | Owner | IDE behavior |
| --- | --- | --- |
| `*.vside`, `Graphs/*.graph.json` | IDE | Read and written by the IDE |
| `*.csproj` | User | Created once with the project (or when missing); never modified afterwards |
| `Generated/*.cs` with the header | Generator | Overwritten when changed; deleted when its graph no longer exists |
| Any other `*.cs` | User | Never written or deleted; compiled together with generated code |

Before writing, `GeneratedFileWriter` checks every target. If a target exists without the header, generation stops with VSP0001 and nothing is written. Files are written atomically (temporary file, then replace) and only when their content changed, so incremental builds stay incremental.

## Escape hatch

Handwritten C# goes in ordinary `.cs` files anywhere in the project. It is part of the Roslyn verification step and of the build. Calling handwritten methods from graphs requires the method-call nodes planned for Phase 3.

## Source map

Every emitted statement is annotated with the ID of the node that produced it. After formatting, annotations are converted to line ranges (`GeneratedSource.SourceMap`). The IDE uses this to highlight a node's code when the node is selected, to select the node when the caret moves in generated code, and to attach Roslyn diagnostics to nodes. The same mapping is the basis for node breakpoints (Phase 5).
